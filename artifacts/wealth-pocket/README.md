# Mira — Personal Finance

Mira is a local-first personal finance app for iOS and Android. The Expo Router app has Home, Alerts, Split, Calendar, Insights, Lending, and Settings sections. It does not send finance records to the workspace API or a remote database.

## Screens

- **Home** — monthly cash-flow headline, quick add, items needing a category, and recent activity.
- **Alerts** — in-app notification feed (loans, repayments, Gmail imports, items needing review). Opening this screen marks everything read automatically; each row can be dismissed individually.
- **Split** — three-way segregation of Income, Expenses, and Savings. Savings is derived from investment contributions minus active loans, so it is a net position rather than a stored kind.
- **Calendar** — day-by-day view with in / out / invested totals.
- **Insights** — animated cash-flow chart (tap a month for exact figures), spending rhythm, category breakdown, portfolio.
- **Lending** — loans given, repayment progress, due dates, WhatsApp reminders.
- **Settings** — Google connection, biometrics, reminders, CSV export, delete all data.

## Category metadata

`constants/categories.ts` is the single source of truth for category lists and their
icons. Screens must not define their own lookup tables — that is what previously let a
category added to the add-transaction sheet fall through to a generic tag icon. Adding a
category in one place gives it an icon everywhere.

## Features

- Record income, expenses, and investment contributions; review transactions by day, month, and category.
- Review recent cash flow, category breakdowns, investment contributions, and lending balances.
- Track money lent, repayment progress, due dates, and local repayment reminders. WhatsApp reminders open a prefilled draft for the user to review; they are never sent automatically.
- Manually import recent payment-alert emails from the signed-in user's Gmail account. Imported items are deduplicated and uncertain categories remain marked for review.
- Export a CSV, learn a merchant category when the user corrects it, toggle biometric unlock, and permanently clear local finance records.

Investment entries represent contributions recorded in the ledger; Mira does not fetch live market prices or calculate portfolio returns. A loan's optional interest rate is retained for reference; repayment balances currently track principal only.

## Local data and security

- Native release configuration enables SQLCipher for SQLite. A random database key and Gmail access token are stored using iOS Keychain or Android Keystore.
- Expo Go and web previews do not include the app's SQLCipher native configuration. Treat them as UI/testing previews only; do not enter real financial records there.
- Gmail access is requested with the `gmail.readonly` scope using OAuth authorization code + PKCE. Sync is manual, recent (30 days, up to 75 listed messages), and reads the message body into memory only. Mira stores parsed transaction fields, not raw email content, and does not send email.
- Google access tokens expire; reconnect from Settings when needed. Disconnecting removes the saved token, not transactions already imported.
- Data deletion clears transactions, learned merchant categories, investments, loans, repayment entries, and scheduled Mira notifications. The Google connection is removed separately. There is no cloud backup or recovery.

This is a local personal finance tool, not a bank, financial adviser, or certified security product.

## Google OAuth setup

Gmail import is inactive until OAuth is configured. The sign-in flow itself is already
implemented in `app/(tabs)/settings.tsx` using `expo-auth-session` with PKCE; nothing in
the code needs to change. It stays hidden behind a setup prompt until a client ID exists
for the running platform.

1. Copy the template and fill in your client IDs:

   ```sh
   cp .env.example .env
   ```

   `.env` is already gitignored. Set only the ID for the platform you are running.

2. In Google Cloud, create a project, enable the Gmail API, and configure the OAuth consent screen for the app and its intended test users.
3. Register OAuth clients for each platform you intend to run. The native clients must match the app's iOS bundle identifier and Android package name; the web client must allow the redirect URI generated by Expo AuthSession. The redirect scheme is `wealth-pocket` (set in `app.json`).
4. Restart the Expo workflow so the new env vars are picked up (`npx expo start -c`).
5. Do not add a client secret to the mobile app. Client IDs are public identifiers; a secret shipped in an app is recoverable by anyone who unpacks it. Tokens are stored at runtime in the iOS Keychain / Android Keystore.
6. Test consent, message parsing, and reconnect after expiry with a non-production Google account before relying on the import.

The app currently has no app-specific bundle identifier or Android package configured; choose those before registering production native Google OAuth clients.

## Sample data (preview mode)

An empty install shows empty states everywhere, which makes it hard to review
screens, charts, and animations. **Settings > Sample data > Load sample data**
replaces the ledger with six months of generated history: recurring salary and
bills, daily spend across the expense categories, monthly SIP and investment
contributions, variable income, four loans (one settled, one overdue, one due
soon), six alerts, and three uncategorised Gmail rows that populate the review
queue.

The dataset lives in `lib/demoData.ts` and is seeded from a fixed PRNG, so
loading it twice produces the same numbers. It is deliberately never loaded
automatically — an app that fabricates balance figures on first launch would be
a genuinely dangerous thing to ship. `isDemoData` is held in memory only, so a
reload drops the flag and the "sample data" banner disappears, which errs
toward under-warning rather than over-warning.

**Preview connected state** under Settings > Google transaction import fakes the
post-authentication UI. It writes no token to SecureStore and never contacts
Google; `readGmailToken()` still reports "not connected" on reload. This exists
so the connected layout can be reviewed before registering a Google Cloud client.

## Theme

`constants/colors.ts` ships two palettes behind identical token names. Light is
the default (`userInterfaceStyle: light` in `app.json`) and carries the glossy
surface tokens: `gloss`, `glossStrong`, `sheen`, `glass`, `glassBorder`, and six
`accentGradients`. `GlossPanel` in `components/finance-ui.tsx` composes them into
a card with a specular highlight.

Two details worth keeping if the theme is edited:

- The sheen is a separate absolutely-positioned overlay, not a stop on the fill
  gradient. That keeps the highlight falloff independent of the brand gradient.
- Elevation shadows borrow the brand hue (`shadow`) rather than using grey. On a
  light background a neutral shadow reads as dirt.

`accentGradient(colors, index)` is the single accessor for accent colours. Pass a
stable index (category position, tab index) so an item keeps its colour across
screens and rebuilds — a colour derived from array order shifts when the list is
re-sorted.

## Developer checks

```sh
pnpm --filter @workspace/wealth-pocket run typecheck
```

The database schema is versioned with SQLite `user_version` (currently 2). Stored in SQLite: transactions, learned merchant mappings, investment contributions, debts, and the in-app notification feed. Preferences and secure credentials are stored separately.

Adding a column or table means bumping `SCHEMA_VERSION` in `lib/database.ts`, updating the
`if (currentVersion > N)` guard, and adding an idempotent `CREATE ... IF NOT EXISTS` block
to the setup script.

## Known constraints

- SQLCipher is enabled in `app.json`, but it only takes effect in a native release build. Expo Go and web previews do not apply it. The database key is generated once and stored in the Keychain / Keystore; losing it means losing the database.
- Android scheduled reminders require the `finance-reminders` notification channel, created on permission grant. Without the permission, reminders are silently skipped by design.
- Charts use `react-native-svg` driven by Reanimated rather than victory-native, to stay within the workspace's `minimumReleaseAge` supply-chain policy and avoid an extra native dependency.
